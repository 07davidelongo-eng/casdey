# casdey

Note: "casdey" is always written lowercase, including at the start of a sentence — never capitalized.

## Project structure
- `CLAUDE.md` — project context and conventions: business context, decisions, pricing, outreach status, and working conventions (everything else in this file).
- `.claude/` — Claude Code's own project configuration: subagents, skills, settings, and any tooling config specific to this project. `.claude/launch.json` starts the local dev server for the browser preview tool. Skills of note:
  - `.claude/skills/cold-outreach/` (invoke with `/cold-outreach`) — read before touching outreach automation. Its `SKILL.md` is the detailed operating spec (environment detection, credentials, salutation rules, batch history); this file only carries the high-level status.
  - `.claude/skills/frontend-design/` — required reading before any frontend/visual work, see `brand assets/CLAUDE_DESIGN.md` for the accompanying screenshot-driven review workflow.
  - `.claude/skills/update-project/` (invoke with `/update-project`) — writes what happened in a session into this file and other project docs (README, `web/SAAS_HANDOFF.md`, `web/SAAS_ROADMAP.md`), so context survives without relying on chat history. Distinct from `/session-handoff` (chat-only, ephemeral) and from user memory (this user's own cross-session recall, not part of the repo).
  - `.claude/skills/push-github/` (invoke with `/push-github`) — commits and pushes to GitHub. `main` is connected to Vercel and auto-deploys on push, so this skill always asks for fresh explicit confirmation before the actual push, even when it's the skill itself being invoked (see the Vercel bullet under Infrastructure).
- `brand assets/` — brand identity. `casdey-brand-guide.html` (v4, "Chalk & Struck Gold", Sep 2026) is the source of truth for colors, type, the logo mark and voice; everything visual must match it, and its tokens are mirrored in `web/src/app/globals.css`. `casdey Logo.png` is the v2/v3 wordmark-only file and is **superseded**: the current lockup is drawn in code (`web/src/components/wordmark.tsx`), don't reuse the PNG. `CLAUDE_DESIGN.md` is Davide's own frontend workflow rules (screenshot-compare against references, brand-asset-first, anti-generic guardrails). `landing page inspiration for casdey.webp` is the reference the current design was built from (Finpay-style fintech layout, adapted with casdey's own palette/copy/illustrations, not copied verbatim).
- `web/` — the casdey website: landing page (`/`), waitlist (`/waitlist`), and eventually the SaaS itself in the same app (Next.js 16 App Router + Tailwind v4, deployed on Vercel with root directory `web`). Waitlist signups are stored in Supabase (EU region). See `web/README.md` for setup, env vars, the waitlist mechanics, and two Supabase gotchas already hit once (bare project URL, explicit `service_role` table grants).
  - **`web/SAAS_V1_PLAN.md` is the single source of truth for the path to a ready V1** — one sequenced plan (Track A build / Track B ops / Track C prod-verify / Track D Davide's final walkthrough) that merges the still-open items from `SAAS_ROADMAP.md`, the readiness gates from `SAAS_ONBOARDING.md`, and the ops tasks. Read it before starting any V1 build work. `SAAS_HANDOFF.md` is the current gym product/deployment reference (rewritten 2026-09-03); `SAAS_ROADMAP.md` is retained as the dated pre-pivot build history (items #1-#10), superseded for V1 purposes by the plan.
- `wiki/` — casdey's business knowledge base (Obsidian vault, not git-tracked, see `.gitignore`): market research, growth/outreach frameworks, competitor notes, strategy exploration too exploratory or too rarely-needed to keep loading into every session via this file. Set up 2026-08-15, schema and conventions in `wiki/CLAUDE.md`, read that before working inside it. Start any query at `wiki/index.md`.

## Business overview

**`casdey HQ` is the one-page business summary, and it is a **Notion** page** — https://app.notion.com/p/3d45f3a51c07818dadd9efadf893c386 (id `3d45f3a5-1c07-818d-add9-efadf893c386`). Seven short sections: the offer, prices, a software-and-monthly-cost table, per-gym unit economics, break-even, current status, and what is open. **Revise it whenever the numbers or the status move** — a price change, a new paid service, the first paying gym, a plan upgrade — and keep it short, because the point is that it stays skimmable rather than complete. It holds the business view; this file stays the engineering and decision record, and the two should not duplicate each other. It sits alongside the **Marketing Plan** Google Doc (see "Marketing plan" below), which owns outreach specifically.

**Why Notion and not a Google Doc.** It was created as a Google Doc on 2026-09-07 and moved the same day. The Drive connector can create, read and trash files but **cannot edit their content** — its `update_file` handles title and parent only — so a doc meant to be revised constantly could only ever be replaced, which changes the file id and breaks every pointer to it. Notion's `notion-update-page` does search-and-replace inside the page, so this one can be kept current in place. The Google original is in Drive's trash if it is ever wanted back.
